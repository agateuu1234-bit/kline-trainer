# 划线 P1c 第 3 片 · 非程序员验收清单：拖节点

> **给验收者**：每条照着「动作」做一遍，对照「预期」，在最后一栏打勾。
> ⛔ 任何一条打了「不通过」，请把**当时的截图或录屏**一并贴到 PR 评论里。

**这一片改了什么**：选中一条线之后，可以用手指**按住线上那个黑点拖动**，把线挪到新位置；拖的时候图表手势（平移、切周期、惯性、双指缩放）都不会被打断或误触发；松手才真正生效，过程中随时可以被第二根手指"打断"（定住当前位置）。

## 做之前先确认的前置条件（⛔ 这几条没弄清楚，后面的真机验收条目**全部验不了**）

1. **先确认"开发者签名证书"和"描述文件"（provisioning profile）是否已经续期**——这两样东西各自有有效期，过期之后手机上直接打不开这个 App，跟这次代码改得对不对毫无关系。本仓记录在案的那一张描述文件在 **2026-10-02** 就已经到期；写这份清单时已经是 2026-10-07，**已经过期好几天**。
   ⛔ **不能靠"编译成功"（Xcode 显示的 `BUILD SUCCEEDED`）来判断证书还有效**——证书过期之后代码照样能编译成功，只是装到手机那一刻才会被系统拒绝；更隐蔽的一种情况是**覆盖安装**：如果手机上已经装着这个 App 的旧版本，直接在旧版本上面覆盖安装，有时会"看起来装上了、也能打开"，其实用的还是旧证书留下的旧安装，这次的新证书根本没有被真正验证过。
2. 如果续期之后换发了**新的**证书，**手机上要手动做一步**：打开「设置 → 通用 → VPN 与设备管理」，找到这个开发者账号，点一下「信任」。不点这一步，系统会直接拒绝打开 App。
3. 最彻底、最不会被"覆盖安装掩盖证书问题"坑到的办法，是先把手机上这个 App **卸载**、再重新安装一次。但**卸载会把这台手机上保存的训练记录、设置等数据全部清空，没法恢复**——这一步**必须先问清楚负责人、拿到明确同意才能做**，⛔ 不能自己决定卸载。
4. 装好之后，要先确认"验收用的测试数据"有没有真的被灌进去。灌数据有一道守卫，**必须同时满足下面四个条件**才会真的灌（少一个就什么都不做、也不会报错）：
   - 本地保存的「训练组缓存」是空的；
   - 「历史记录」条数是 0；
   - 没有保存着一局没打完的「未完成对局」；
   - 「设置」还是出厂默认值（没有被改过手续费率 / 本金 / 显示模式等）。
   （四个条件的判断依据：`ios/Contracts/Sources/KlineTrainerPersistence/DebugFixtures/AppContainer+DebugSeed.swift:17-25`）
   ⇒ 判断数据有没有真灌进去，要看**灌之前和灌之后的对比**（比如历史记录条数从 0 变成有值），⛔ **不能只看"App 打开了"**。
5. 下面每一条验收条目的判断标准，都是「**改动前 vs 改动后的对比**」，不是「App 能打开、能点一下就算过」。

## 已知的设计限制（不是 bug，验收前先读一遍，免得把它们当成缺陷报上来）

- 几条线叠在一起时，点一下**只能**选中最上面（最后画的）那条；
- 想把线放到比屏幕上现在显示的价格更高 / 更低的位置，**做不到**——得先把图缩小，或者上下滚动，让那个价位先出现在屏幕里。这是设计决定，**不是 bug**；
- 锁上的线**选得中、看得见黑点，但拖不动**；
- **手指正按着拖黑点时，另一只手去点别的线，不会换选中**——松手之后再点就正常了。这是刻意的，**不是 bug**；
- **手指正按着拖黑点时，底栏的 🗑 垃圾桶 / 🔒 锁 / ↩ 撤销 / ↪ 前进，以及样式面板，都会变灰**——松手后立刻恢复可用。同样是刻意的，**不是 bug**。

### A. 一条具名结构性残留：`ChartGestureArbiter` 这一层没有测试缝

它有**三个表现**（同一个根因，不要当成三件独立的事）：

1. **真实长按识别器驱动不起来**：`ios/Contracts/Package.swift` 只有两个 `.testTarget`（Contracts / Persistence），没有任何 UI Testing / app host target；`grep -rn "UILongPressGestureRecognizer" ios/Contracts/Tests` 实测 0 命中。SwiftPM 单元测试进程本身没有可承载"真实触摸注入 + `UIApplication` 主循环"的宿主，这是结构性缺口，不是没试。⇒ 对应真机验收条目 **#14 / #15**，断言细分：(1a) 手指按在节点上、真的等够 `minimumPressDuration`（UIKit 默认约 0.5s）让长按识别器走到 `.recognized`；(1b) 之后拖动必须拖的是节点；(1c) 等待识别期间不产生平移/不切周期；(2a) 按在节点外，同样的时序下必须照常平移。
2. **`ChartGestureArbiter.singlePanRouteState`**（`ChartGestureArbiter.swift:75`）是 `private var`，唯一读写它的 `handleSinglePan`（`:177`）是 `@objc private`，没有 `...ForTesting` 入口——`@testable import` 对 `private` 无效。这让"候选已接受进入 `.nodeDrag` 路由 + 期间周期切换让 `nodeDragOwner` 变 nil + 同一手势继续"这类组合场景在自动化测试里驱动不起来（Task 14 变异 #37，详见下方 B.17）。
3. 现有的第二指打断测试（`secondFingerInterruptionFinalizesInPlace`）为了绕开上述两个结构限制，直接调用 `handleNodeDragForTesting` 并**手工指定** translation，完全绕开了真实 `ChartGestureArbiter`——对"仲裁器层把 translation 传错"这**整类**缺陷（不止"回弹"这一种变异）判别力为零（Task 14 变异 #40，详见下方 B.18）。

⇒ **补偿手段**：把它写成真机验收条目（上面的 #14/#15；以及第二指打断、长按后拖、取消后再拖等场景），**不用自动化测试兜底**。

⭐ **这四条的共同点**：「已做 / 已验」的主张若没被第三方复核，就可能是过度声称。本片一共有 **3 次**报告的 green/sync 主张没通过控制者复核——这条经验本身值得记在这里。

### G. 措辞纪律提醒："不可构造" ⛔ 不等于 "没有缺陷"

Task 14 有 3 条变异（#18/#24/#25，见上方 B.12/B.14）在当前接口签名下**不可构造**（函数签名里根本没有那个输入参数）。控制者已裁定接受**签名级证据**（签名是当前代码的可核事实，不是对行为的预测；要"真改签名再验证"得跨 3-4 个文件、改 17 个调用点，那是修改被测对象本身，超出本片范围）。
⇒ 残留里只能写「该变异在当前接口下不可构造（签名级证据：file:line + 逐字签名）」。
⛔ **不得**写成「我们验证了这里没有缺陷」——两者是完全不同的主张，混写会让后续读者高估覆盖面。
