# QMT 4a-2b 切片 S3 验收清单（`--init-cluster-marker`）

**这份清单写给不写代码的人。** 你要做的只有两件事：把命令**一行一行**粘进终端，然后照着「预期」看屏幕上的字。

**术语先说清楚：**

- **终端**：Mac 上那个黑底白字、可以敲命令的窗口（「启动台」里搜「终端」）。
- **容器（Docker）**：一台装在你电脑里的「小电脑」，本次用它跑数据库。它停了就打不开数据库。
- **PostgreSQL（下称「数据库」）**：存数据的仓库软件。本次验收跑在**真的**数据库上，不是模拟件。
- **维护库**：这套工具用来记账的那个数据库，里面有三张表：标记表、建库意向表、登记表。
- **标记**：写在维护库里的一句话，意思是「这台数据库整机是给 pilot 专用的，可以被整个毁掉」。
  **本工具只会写标记，从不删标记**——删标记是人工动作。
- **孤儿行**：建库建到一半崩了，留在「建库意向表」里的一条没人认领的记录。它会占住那个名字，
  挡住后面的建库。S3 这一片就是负责把它清掉的。
- **占用锁**（英文 advisory lock）：数据库里的一块「有人正在用」的牌子。清孤儿行之前必须先拿到牌子，
  否则会把**一次正在进行的建库**的记录删掉。

⚠️ **每条命令都要在同一个终端窗口里跑。** 换窗口的话，第 0 步设的那几个变量会全部丢失，
后面的命令会报「用法：…」而不是真的跑起来——那不是程序坏了，是变量没了，回到第 0 步重设即可。

⚠️ 屏幕上的字很多，**只看「预期」点名的那一行**，别看别的行。

⚠️ 每个灰底框里**只有一行**命令，整框选中复制、粘贴、回车。不要把两框并成一次粘贴。

## 第 3 步：这一片到底改了什么（读一遍，能对上就行）

| 改动 | 一句话解释 |
|---|---|
| 孤儿行清理 | 建库崩在半路留下的记录会被自动清掉，但**只清「已经超过 24 小时」或「那个数据库真的已经不存在了」的**。 |
| 先拿牌子再删 | 删之前必须先拿到那把「有人正在用」的牌子，拿不到就跳过——防止把**别人正在建的库**的记录删掉。 |
| 牌子必须还 | 拿了牌子用完必须还，还完还要**再回头确认真的还掉了**。不还的话那个名字会被永久占住。 |
| 判断在锁里做 | 「超没超时、库还在不在」这两个判断，是在拿到牌子之后由数据库**当场**算的，不是提前算好再删。 |
| 标记写在最后 | 「这台机器是 pilot 专用」这句话现在是整个流程的**最后一句**才写进去。它写下去就删不掉了（契约规定本工具从不删标记），所以必须等所有检查都过了才写。 |
| 时钟用对了 | 判断「超没超 24 小时」用的是**当前这一刻**的时间，不是「这笔事务开始时」的时间。用错的话，一条真的已经过期的记录会被当成还新鲜，于是永远清不掉。 |

## 第 4 步：不通过怎么办

| 屏幕上的现象 | 含义 | 你该做什么 |
|---|---|---|
| `用法：DSN='postgresql://...'` | 第 0 步的变量丢了（多半换了终端窗口） | 回第 0 步，从 0-4 重粘一遍 |
| `拒绝运行：DSN2 未设置` | 少设了一个变量 | 重粘 0-6 和 0-8 |
| `拒绝运行：这些库名匹配 … 但不是本脚本建的` | 上一次跑到一半被中断，留下了残骸 | 粘下面那条清理命令，然后重跑 1-2 |
| `Cannot connect` / `Connection refused` | 数据库容器没开 | 重粘 0-1 |
| 条数对不上（如 `829 passed`、「47 档」） | 真的有东西坏了 | **不要自己改**，把整屏输出发给我 |

清理残骸用这一条（只有上面第三行那种情况才用）：

```
QMT_VERIFY_FORCE_CLEANUP=1 "$PY" backend/scripts/verify_pilot_db_lifecycle.py
```

## 附：本次实施留下的、已知没有覆盖到的地方（如实登记，不是遗漏）

1. **脚本的库名扫描器看不见拼接出来的名字**：新场景的数据库名是用 `"lifecycle_r37"`
   拼成 `kline_pilot_lifecycle_r37` 的，而那个扫描器只认**整段写死**的名字，
   所以「新库名有没有登记进白名单」这件事**目前仍靠人工**。
   这次已登记齐，并用变异实测坐实过：故意漏登记一个，下一次运行会**直接拒绝启动**并点名它。
   把扫描器改成能看穿拼接，要动公共代码并回头核对既有 30 个场景，是**另一片独立的工作**，本片不做。
2. **「不数 autovacuum 后台进程」那一向没有常驻档**：要做的话得改整台数据库的配置，
   对验收脚本侵入太大，沿用既有做法：由一次性实验坐实并记进计划。
3. **一次最终失败的初始化仍可能在维护库里留下那三张表**：建表和后续检查不可能是原子的。
   这是**已接受的残留**，与「标记」分开对待——表只是结构、不授权任何事；
   而标记是信任声明，它已经被挪到整个流程的最后一句。
