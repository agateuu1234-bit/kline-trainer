## 二、共享地基放哪（关键决定）

**放 4b，4a 不引用，4c 引用 4b。**

共享地基＝`open_root` / `open_under` / 归属标记与认领协议 / 耐久提交协议（fsync 闭合清单）/
锁纪律（`flock` 语义、**取锁早于发布归属**，R97-F2）/ 对象 × 维度矩阵 + 5 条机械检查 / 文档级章节权威性不变量。

判据：
- **4a 完全不碰目录** —— 它是 `assert_pilot_db_allowed` + 集群闸 + pilot 库生命周期，
  `output_dir` 在它那里只是 `pilot_meta` 里的一个字符串值。**故 4a 不需要引用共享地基，零依赖。**
- **4b 是第一个真正创建并写目录的工具**（`--dest` 创建、`--source` 读），共享地基天然属于它。
- **4c 在 4b 之后合并**，引用 4b 是**后向引用**，不产生前向依赖。

⚠️ **`--output` 的归属/锁纪律写在 4c**（它是 `--output` 的唯一使用者），但**必须显式声明「与 4b `--dest` 同规格，
差异只有 EEXIST 那一档」**（R91-F2 / R92-F1 的结论），并在 4c 的机械检查里保留「三个目录 × 五维度」那一格。

## 三、跨 spec 的引用纪律（防止再犯 97 轮里的那类错）

1. **同一条规则只在一份 spec 里定义**，其余两份**引用 + 不复述**（这是旧 spec 文首那条文档级不变量的跨文件版）。
2. **跨 spec 引用必须写成「见 `<文件名>` §X」**，不得只写「见 §X」——三份文档的 §号会各自重排。
3. **五条机械检查（旧 §11 立）三份各自保留一份**，但**检查范围限本文件**；
   涉及跨文件对象（如 `verdict` 枚举）时，检查项须显式写明「须同时核 `<另一份>` §X」。
4. **`verdict` 枚举、错误码枚举、报告 schema 的唯一权威在 4c**；4a/4b 只声明「我会产生哪几个」，
   由 4c 收口成闭合枚举。**新增错误码时两边都要改，且 4c 是定义处。**

## 五、切分过程本身的安全纪律

**本会话已因「按起点 + 搜索终点定义删除区间」误删过 §6–§11 约 1100 行**（当轮已归档为教训）。
故切分一律用**程序化抽取 + 断言**：
- 按 `##`/`###` 标题行定位边界，**断言每段行数落在预期区间**；
- 抽取后**断言三份新 spec 的总行数 ≥ 原 spec 行数 × 0.9**（允许去重，但不允许整段丢失）；
- **原 spec 一个字节都不删**，只在文首加标注。
