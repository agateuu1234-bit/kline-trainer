## 判据分三层，每层都是被实测打出来的

### ① 发现层：正则，不是固定字面量

`text.find("INSERT INTO training_sets")` **区分大小写**，且只认「`INTO` 与表名之间恰好一个空格、无 schema 限定」一种拼法。实测：小写 / 换行 / `public.` 三种**合法且缺字段**的写法**全部溜过**，而既有 12 处仍满足防空转计数 ⇒ **新写入方可静默绕过**。

### ② 判定层：按【列名集合】，不是子串

一句 `/* schema_version uses the default */` 注释就能把子串判断喂饱，而**真列并不在场**。
⇒ 先剥 SQL 注释（`/* */` 与 `--`），再按逗号切 token、剥引号后按**整个标识符**比对。
⭐ 所以一个叫 `my_schema_version` 的列**不会**被误判为通过（变异已验）。

### ③ 兜底层：一张故意放宽的粗网

精确正则再宽也总有够不着的拼法（表名被劈成 `"INSERT INTO training_"` + `"sets …"`）。
⇒ 凡「像是往 `training_sets` 写」却**没被精确正则认领**的，一律报「**判据够不着**」**让测试红**。
⛔ **不许把「断定不是目标」和「判据够不着」混进同一个分支** —— 两者会互相伪装成对方。宁可偶尔误报（红了有人看），也不要漏报（绿了没人知道）。

## 第五次攻破后：发现层换做法（不再往字符类里补字符）

Codex 再次判 **needs-attention**：`INSERT INTO public./* target table */training_sets`
—— **schema 限定符与表名之间夹注释**，同时绕过精确正则与粗网。**我复现了。**

### ⚠️ 到这里必须承认：我一直在打地鼠

发现层被攻破的**五次**，每一次我的反应都是「往间隔字符类里再补一个字符」：

| 次 | 攻破形态 | 我当时的补法 |
|---|---|---|
| 1 | 大小写 / 换行 / `public.` 限定 | 固定字面量 → 正则 |
| 2 | 关键字之间夹注释 | 间隔类补 `/* */`、`--` |
| 3 | `+` 拼接 | 间隔类补 `+`、`\` |
| 4 | 表名被劈开 | 加粗网兜底 |
| 5 | **限定符与表名之间夹注释** | ← 如果继续，就是再补一个字符 |

**字符类永远数不全。** ⇒ 换**结构性**做法。

### 新做法：先抹平、再用简单正则

先把**干扰物**换成**等长空白**（位置 1:1 保持、换行保留 ⇒ 行号不会错），再扫抹平后的文本。干扰物只有两类：
1. SQL 块注释 `/* … */` —— 可以出现在语句的任何缝隙里；
2. Python 字符串拼接的痕迹 `"` `'` `+` `\` —— 它们**永远不属于标识符**。

抹平之后，发现层只剩一条**简单**正则：

```
insert(?:\s|--[^\n]*\n)+into(?:\s|--[^\n]*\n)+(?:public\s*\.\s*)?training_sets
```

⚠️ **等长是硬要求**：抹平后的下标要能直接映射回原文，否则报出来的行号是错的。
⚠️ `--` 行注释**不做全局抹平**（它在 shell / YAML 里另有含义，全局抹会吃掉同一行后面的真 SQL ⇒ 制造**漏报**）；只在关键字之间的间隔里局部容忍。

⭐ **换完之后实现反而更简单了** —— 手工调出来的一长串字符类没了。

| 解析层 | 4 | ✅ |

## 第六次攻破：表示空白的**转义序列**

Codex 再判 **needs-attention**：`"INSERT INTO\\ntraining_sets (…)"` —— Python 字面量里的
`\\n` 执行时是**合法 SQL 换行**，但**源码文本里是反斜杠 + 字母 `n` 两个字符**。
抹平只抹掉了反斜杠，留下一个 `n` ⇒ 发现层当场瞎掉。**我复现了。**

**修法**：按**整个转义序列**抹成等长空白，而不是只抹反斜杠。
⛔ 次序有讲究：空白转义必须在单字符拼接痕迹**之前**处理 —— 否则反斜杠先被抹成空格，留下的 `n` 就再也认不出来了。

⭐ **这一类是可穷举的**（与前五次不同）：SQL 里的空白只有 空格/制表/换行/回车，对应的转义写法就那么几种。

## 第八次攻破：**注释里的右括号**提前终止配平扫描（真假绿）

⚠️ **这一次不在发现层，在解析层** —— 而且是一次**真正的假绿**（守卫报绿、语句确实缺字段）。

```sql
INSERT INTO training_sets (stock_code /* , schema_version) */, stock_name, …)
```

发生了什么（三步连锁）：
1. 配平扫描只数括号 ⇒ **注释里面**那个 `)` 提前终止扫描；
2. 截出的片段是 `(stock_code /* , schema_version)` —— 其中的注释**未闭合**；
3. 剥注释的正则匹配不到未闭合的注释 ⇒ `schema_version` 字样**作为「列名」幸存** ⇒ 判为通过。

而 PostgreSQL 会**忽略那段注释**、按缺字段处理 ⇒ 用 `DEFAULT 1`。**正是本守卫要挡的东西。**

**修法**：配平扫描本身改成**注释与引号感知** —— 遇到 `/* */`、`--…\n`、`'…'`、`"…"` 整段跳过，不参与括号计数。⛔ 不是事后剥注释（事后剥救不了「已经截断错了」）。

### 解析层一次穷举

| 变体 | 结果 |
|---|---|
| S1 注释里有右括号（codex 报的） · S2 注释里有左括号 · S3 行注释里有右括号 | 🔴 红（缺字段）|
| S4 引号里有右括号 · S5 注释里整段伪造列清单 | 🔴 红（缺字段）|
| S6 注释未闭合 | ⚠️ 兜底「判据够不着」—— **正确**：确实判不了 |
| **S7 正常带 `schema_version` 的语句（对照组）** | 🟢 **绿** |

⭐ **S7 是最重要的一条**：它证明守卫**不是恒红**。前面所有变体都在证明「坏的会红」，
S7 证明「**好的会绿**」—— 两个方向都有判别力，判据才算数。

## 第九次攻破：**嵌套**块注释 —— 以及四份重复实现的合并

PostgreSQL 的 `/* */` **可嵌套**，而我有**四处各自为政**的注释处理，全是非贪婪正则/内联跳过，
在**第一个** `*/` 就停：

```sql
INSERT INTO training_sets (stock_code /* outer /* inner */ , schema_version, */ , stock_name, …)
```

PostgreSQL 看：整段都是注释 ⇒ `schema_version` **被注掉、列不在场**。
我的守卫看：剥到第一个 `*/` 就停 ⇒ 残留的 `schema_version` 字样**被当成列名** ⇒ **假绿**。

**修法**（按 codex 建议，也是本仓「同一条判据存在于多处实现」教训的正解）：
**全片只留一个嵌套感知的块注释扫描器**，发现层 / 配平扫描 / 列名提取**三处共用**，直接**去掉重复**。

| 变体 | 结果 |
|---|---|
| N1 嵌套注释藏字段（codex 报的） · N2 三层嵌套 · N3 嵌套注释在关键字之间 · N4 嵌套注释里有右括号 | 🔴 红（缺字段）|
| **N5 对照：嵌套注释但字段真在场** · **N6 对照：正常语句** | 🟢 **绿** |

### ⚠️ 合并过程中我自己引入了一个回归 —— 被防空转断言当场抓住

第一版扫描器写的是「**未闭合的 `/*` 一路抹到文末**」（想对齐 PostgreSQL 的行为）。**当场闯祸**：

`.github/workflows/schema-smoke.yml` 的 `paths:` 里有 `'backend/sql/**'` ——
`/` 加 `*` 正好构成 `/*`，而全文**没有** `*/` ⇒ **从第 6 行一路抹到文末**，
该文件里 **5 条 INSERT 全部消失**，守卫只剩 `checked=5`。

⭐ **`assert checked >= 12` 这条防空转断言当场报红**，否则这就是一次「守卫自己把自己弄瞎、却报绿」。

**改法**：找不到配对的 `*/` 就**不抹**（当它不是注释）。
⇒ **失败必须往「吵」的方向倒**（不抹 ⇒ 可能误报 ⇒ 有人看），
  ⛔ **不能往「瞎」的方向倒**（乱抹 ⇒ 漏报 ⇒ 没人知道）。

## 第十次攻破：**行注释里的 `/*`** 把真语句抹没了（与第九次方向相反）

```sql
-- /*
INSERT INTO training_sets(…) VALUES (…);   ← 这条是【要执行】的
-- */
```

PostgreSQL：两行 `--` 各是独立的行注释，**中间那条 INSERT 照常执行**、用 `DEFAULT 1`。
我的扫描器：把第 1 行的 `/*` 当起点、第 3 行的 `*/` 当终点 ⇒ **把真语句整段抹掉** ⇒ 发现层看不见 ⇒ **假绿**。

⚠️ **与第九次方向相反**：第九次是「抹太多（未闭合 `/*` 一路抹到文末）」，这次是「**抹错地方**」。
两次的根因是同一个：**扫描器只认块注释、不认行注释**。⇒ 改成**先认行注释、再认块注释**。

| 变体 | 结果 |
|---|---|
| T1 `-- /*` 包夹真语句（codex 报的） · T2 `-- */` 在前 · T3 行注释里同时有 `/*` 和 `*/` | 🔴 红（缺字段）|
| T4 块注释里有 `--` · T5 块注释里有 `--` 和 `*/` | 🔴 红（缺字段）|
| T6 真块注释包住真语句 | 🟢 绿 |
| **T7 行注释注掉真语句** | 🔴 **红 —— 见下方「有意保留的不对称」** |
| T8 对照：裸的缺字段语句 | 🔴 红 |
| **T9 对照：裸的带字段语句** | 🟢 **绿** |

### ⚠️ T6 / T7 的不对称是【有意保留】的，不是漏修

| | 发现层看得见吗 | 缺字段时 |
|---|---|---|
| 被 `/* */` 注掉 | 看不见（块注释被抹成空白） | 🟢 绿 |
| 被 `--` 注掉 | **仍看得见** | 🔴 红 |

**为什么不改成一致**：

① 要一致就得在发现层也抹掉行注释，而那会让
`psql --dbname=x -c "INSERT INTO training_sets(…)"` 这种写法**整条被抹掉** ⇒ **静默漏报**。
实测当前作用域内「同一行 `--` 出现在 INSERT 之前」的行数为 **0** —— 但这是**今天**的事实，**不是结构保证**。
⛔ 失败要往**吵**的方向倒，不往**瞎**的方向倒。

② 「注掉的、缺字段的 INSERT」本身就是**埋着的雷** —— 取消注释只要删两个字符。
红在这里是合理的：**要么补上字段，要么把那行删掉。**

⇒ 被 `/* */` 注掉且缺字段的语句**确实会溜过去**，这条与「表名来自变量」一样，
记为**已知边界**，补偿措施同样是数据库层的 fail-closed（残留 **TS1-R1**）。

## 第十一次攻破：**源码换行 ≠ 运行时换行**（第 4 次真假绿）

```python
"INSERT INTO training_sets (stock_code, …, "
"-- optional metadata: "
"schema_version,\n"
"file_path, content_hash) VALUES (…)"
```

- **源码里**：`-- optional metadata: ` 和 `schema_version,` 在**两行** ⇒ 我的守卫认为 `--` 只注掉第一行，`schema_version` **在场**；
- **运行时**：相邻字面量拼成**一行** `-- optional metadata: schema_version,` ⇒ PostgreSQL 看到 `schema_version` **被注释掉**、列不在场 ⇒ 用 `DEFAULT 1`。

⇒ **守卫报绿，数据标错。** 第 4 次真假绿。

### 修法：不猜，改成**明说判不了**

要真正判准这一类，得上 **AST 解析**（先把相邻字面量拼出来再看 SQL）。本轮**不走那条路**，
而是把「悄悄猜错」换成「**吵着说判不了**」：

> **只有 `.sql` 文件能保证「源码换行就是 SQL 换行」。** 其它宿主（`.py` / `.sh` / `.yml` / `.md`）
> 里 SQL 是字符串，换行可能来自 `\n` 转义或相邻字面量拼接。
> ⇒ **非 `.sql` 文件的列清单里只要出现 `--`，一律报「判据够不着」让测试红。**

| 变体 | 结果 |
|---|---|
| U1 相邻字面量拼出注释（codex 报的） | ⚠️ **兜底「判不了」**（原为假绿）|
| U2 `--` 与字段在同一个字面量 | ⚠️ 兜底 |
| U3 `--` 但字段在 `\n` 之后（运行时**真的在场**）| ⚠️ 兜底 —— **保守**：判得出也不猜 |
| **U4 对照：无 `--` 且字段在场** | 🟢 **绿** |
| V1 `.sh` heredoc 里真换行 + `--` 注掉字段 | ⚠️ 兜底 —— 同样保守 |

⚠️ **U3 / V1 是有意的保守**：那两种情况其实判得出来，但判据无法**结构性地**区分
「源码换行是不是运行时换行」⇒ 宁可多说几次「判不了」（**吵**），
也不要有一次「猜错了还报绿」（**瞎**）。

⇒ 代价：往列清单里写 `--` 注释的人会被要求改写（删掉注释或挪到列清单外）。
   这个代价是可接受的 —— **列清单里本来也不该塞注释**。

```sql
SELECT '/*';
INSERT INTO training_sets(…) VALUES (…);   ← 这条是【要执行】的
SELECT '*/';
```

我的扫描器把第 1 行字符串**里**的 `/*` 当成注释起点、第 3 行的 `*/` 当终点 ⇒ **把真语句抹掉** ⇒ **假绿**。

### ⚠️ 这是同一个形状的第三次

| 轮 | 藏在哪里 | 我当时的修法 |
|---|---|---|
| 10 | **行注释**里的 `/*` | 加「先认行注释」 |
| 12 | **SQL 字符串**里的 `/*` | ← 若照旧就是再加一个上下文 |

⇒ **不再逐个补上下文**，改成**按词法走一遍**：行注释 / 字符串 / 块注释**三种区域各自跳过**。
注释定界符**只有在不处于别的词法上下文里时才算定界符** —— 这才是这一族的根。

| 变体 | 结果 |
|---|---|
| W1 SQL 字符串里的 `/*`（codex 报的） · W2 字符串里的 `--` · W3 双引号标识符里的 `/*` · W4 `''` 转义后接 `/*` | 🔴 红（缺字段）|
| W5 行注释里的 `/*`（第 10 轮的回归） | 🔴 红 |
| W6 真块注释包住真语句 | 🟢 绿 |
| **W7 对照：裸的缺字段** 🔴 · **W8 对照：裸的带字段** 🟢 | 两向皆对 |

**8 / 8 行为正确。** 干净树 `1 passed`；整套后端 `1506 passed`。

## 第十三次攻破 → **换掉整个思路：不再做任何「全局抹除」**

codex 第 13 轮两条：`.sh` heredoc 里的 `'/*'`、`.sql` 的**美元引号** `$$/*$$`。

### ⚠️ 到这里，形状已经很清楚了

| 轮 | 抹掉了什么不该抹的 |
|---|---|
| 9 | 未闭合的 `/*` ⇒ 抹到文末（`paths:` 里的 `'backend/sql/**'`）|
| 10 | **行注释**里的 `/*` ⇒ 抹掉中间的真 INSERT |
| 12 | **SQL 字符串**里的 `/*` ⇒ 同上 |
| 13 | `.sh` heredoc 里的 `'/*'`、`.sql` 的 `$$/*$$` ⇒ 同上 |

**四次，同一个形状：抹掉了不该抹的东西 ⇒ 真语句从发现层消失 ⇒ 假绿。**

我前三次的修法都是「**再教它认一种上下文**」。但上下文是**开放**的 ——
美元引号、`E'…'`、`U&'…'`、宿主语言的各种字符串形式…… **数不完**。

### ⇒ 换思路：**抹除本身**才是问题

**抹除是破坏性操作，而破坏的代价是漏报（瞎）。**

改成：**不抹任何东西**，让「`INSERT` … `INTO` … 表名」这个**很短的构造内部**的间隔
直接容忍干扰物（空白 / 行注释 / 块注释 / 宿主引号 / `+` / 续行 / 空白转义）。

⭐ **关键差别**：间隔只作用在一个**很短的构造**里，所以它认不全某种字符串语法时，
最坏结果是**匹配不上 ⇒ 落进粗网 ⇒ 报「判据够不着」（吵）**，
⛔ **而不会像抹除那样把整条真语句变没（瞎）**。

### ⚠️ 第一版「不抹除」换来了另一组失败 —— 两件事都得做

只改发现层之后，第 8 / 9 轮（**解析层**的括号与嵌套注释）当场回归。
⇒ 解析层必须**自己**认注释：配平扫描与列名剥离都改成**嵌套感知**，找左括号时也跳注释。

### 十三轮全形态总回归（19 例）

| 类 | 例 | 结果 |
|---|---|---|
| 发现层历次攻破 | 13a 美元引号 · 13b heredoc · 12 字符串里的 `/*` · 10 行注释里的 `/*` · 7 点号后行注释 · 5 限定符间块注释 · 4 关键字间块注释 · 3 小写/限定名/换行 · 6 `\n` 转义 · P1 `+` 拼接 · G1 `INTO` 后断行 | **全红** |
| 解析层历次攻破 | 9 嵌套注释藏字段 · 8 注释里的右括号 · B4 无列清单 · G3 表名劈开 | **全红**（走兜底「判不了」分支）|
| 判定层 | E4 列名叫 `my_schema_version` | 🔴 红 |
| **正向对照** | 裸带字段（`.sql`） · py 带字段 | 🟢 **全绿** |

**19 / 19 符合预期。** 整套后端 `1506 passed`。

⚠️ **诚实记一笔**：第 8 / 9 / B4 / G3 现在走的是**兜底分支**（报「判据够不着」）而不是
干净的「缺字段」分支 —— **安全性不变（都是红）**，但**报文精度下降了**。
这是「不抹除」换来的代价，我选择接受：**吵得不够精确**，好过**瞎得很体面**。

## 第十四次：**第一次是假阳性** —— 而且我的回归套件没抓到它

## 第十五轮（codex）：关键字之间的**嵌套**注释 —— 正则做不了嵌套

### 缺陷

```sql
INSERT /* outer /* inner */ outer */ INTO training_sets (…) VALUES (…);
```

这是**合法 PostgreSQL**（块注释可嵌套）。而发现层的两条正则里，关键字间隔
`_GAP` 用的是**非嵌套**的注释模式 —— 它在**第一个** `*/` 就停，后面剩下
`outer */ INTO …` 匹配不上 ⇒ **精确网和粗网同时落空** ⇒ 语句从发现层消失 ⇒ **假绿**。

### ⭐ 这是我自己第十三轮那个判断的直接后果

第 13 轮我把注释处理**从（嵌套感知的）抹除搬进（非嵌套的）正则间隔**时，
心里判断过一句「关键字之间放嵌套注释很荒谬」—— **那个判断是错的**。
它在守卫**自己声明的覆盖范围**（字面量 SQL）之内，荒谬与否不是判据。

### 修法：发现层改成**非破坏性的游标扫描器**，既不抹除、也不用正则

两条约束是十五轮打出来的，**缺一不可**：

| 约束 | 由哪几轮逼出来 | 为什么 |
|---|---|---|
| **不抹除** | 9 / 10 / 12 / 13（四次） | 抹除是**破坏性**的，抹错 ⇒ 真语句消失 ⇒ **漏报（瞎）**。每次修法都是「再教它认一种上下文」，而上下文是**开放**的（`E'…'`、`U&'…'`、heredoc、美元引号……）—— **数不完** |
| **不用正则** | 15 | 正则**表达不了嵌套** |

游标扫描器（`_skip_gap` / `_match_word` / `_find_inserts`）同时满足两条：
**只前进、不改写原文**，且**手写的跳过逻辑可以嵌套感知**。
认不全某种语法时，最坏结果是**推进失败 ⇒ 落进粗网报「判不了」（吵）**，
⛔ 而不是把真语句变没（**瞎**）。

### 重构自带的两处残渣（都在本轮一并修掉）

1. **潜伏的 `NameError`**：兜底分支仍在引用已删除的正则匹配对象 `m.group(0)`。
   它只在「命中未知写法」时才触发 ⇒ 干净树上**看不见**，真出事那天**守卫自己崩掉**。
2. **粗网丢了对 `_` 的容忍**：旧正则写的是 `training[\s_"'+\\]*sets`，
   新扫描器忘了 `_`。实测 **G3「表名劈开」（`"…training_" "sets…"`）由「抓到」退回「假绿」** ——
   靠总回归抓出来的，不是靠读代码。

|---|---|---|
| 攻击样本注入 `.sh` | 27 | 🔴 全红（含 R15 嵌套注释的 3 种位置） |
| 攻击样本注入 `.sql` | 14 | 🔴 全红 |

## 第十六轮（codex）：`--` 行注释遇上**转义**换行 —— 以及它暴露的更大问题

### 缺陷（codex 报的那条）

```python
q = "INSERT -- seed row\nINTO training_sets (…) VALUES ($1,…,$6)"
```

运行时 `\n` 就是换行，这是**合法 SQL**。但**源码文本里没有物理换行** ——
`_skip_gap` 的 `--` 分支只找物理 `\n`，于是行注释「永不结束」⇒ 推进失败 ⇒ **假绿**。

**修法**：行注释的终止符改成「物理换行 **或** 换行的转义写法」。
换行的转义写法是**封闭集合**（`\n` `\r` `\x0a` `\x0d` `\012` `\015` `
` `
`），
照抄全集即可，不必打地鼠。

### ⭐⭐ 真正的问题：我注释里写的那条不变量【从来没兑现过】

代码里白纸黑字写着：

> 认不全某种语法时，最坏是**推进失败 ⇒ 落进粗网报「判不了」（吵）**，
> ⛔ 而不是把真语句变没（**瞎**）。

**这句话当时是假的。** 因为粗网和精确网**共用同一个 `_skip_gap`** ——
间隔一旦解析不动，两张网会**同时**落空。所谓的「兜底」根本不存在。

⇒ 新增**第三张网**（`_LAST_RESORT_RE`）：它**完全不解析间隔**，只认三个词
（`insert` … `into` … `training`+`sets`），中间允许任何字符，
⛔ 但**不许跨** `(` `)` `;` —— 这一条是被干净树上的误报逼出来的：
`INSERT INTO p15_targets (id) SELECT id FROM training_sets` 是往**另一张表**写的合法语句，
中间的 `(id)` 正好把它排除掉。实测该网在干净树上**多报 0 条**。

### 我自己另外挖到的六条（同轮一并修）

评审在跑的时候我按 PostgreSQL 词法把间隔又穷举了一遍，挖到**六条假绿**：

## 第十七轮（codex）：连**注释定界符自己**都被劈开 —— 以及我为什么换掉整条路线

### 缺陷

```python
q = ("INSERT INTO training_sets (stock_code, /"
     "* optional columns, schema_version, *"
     "/ stock_name, …, content_hash) VALUES ($1,…,$6)")
```

运行时这三段拼成 `… (stock_code, /* optional columns, schema_version, */ stock_name, …)` ——
`schema_version` **在注释里**，PostgreSQL 会用 `DEFAULT 1`。
而**源码文本里根本不存在 `/*`**（是 `/"` 和 `"*`），剥注释那一步什么也剥不掉，
`schema_version` 作为「列名」幸存 ⇒ **假绿**。

### ⭐⭐ 这是同一条根的第三次命中，我该早两轮换路线

「**源码文本 ≠ 运行时字符串**」这条根：

| 轮次 | 形态 |
|---|---|
| 11 | 相邻字面量拼接，`--` 注掉了下一段里的 `schema_version` |
| 16 | `--` 后面是**转义**换行 `\n`，源码里没有物理换行 |
| 17 | **注释定界符本身**被劈开 |

前两次我的修法都是「再教扫描器认一种写法」。而「**数不完**」这四个字，
就写在本文件我自己的注释里 —— 我对发现层认了这个道理，对**判定层**没认。

⇒ 换路线：`.py` 宿主改用 **Python 自己的语法树**。`ast` 会把相邻字面量
**折叠成一个常量**、把转义序列还原，得到的就是运行时真正交给 PostgreSQL 的那串字符。
这不是「多认一种写法」，是**把问题从『猜』变成『解』**。

⚠️ `ast` 解不动的写法（`+` 拼接、`.format()`、f-string 的变量部分）不会凭空消失：
**兜底网始终扫原文**，它们落进「判据够不着」（吵），不是「瞎」。实测 `+` 拼接劈开表名 ⇒ 判不了。

⚠️ 解析失败（语法错误的 `.py`）必须**退回扫原文**，⛔ 不能当成「没有字面量」——
那是把解析失败伪装成检查通过（本仓老教训：**报「0 违反」的扫描必须先证明它能报非 0**）。

### ⭐⭐⭐ 变异验证挖出的真问题：整套判据【只能靠临时脚本验】

十七轮里我一直用临时脚本往真文件里注样本来验证。**临时脚本不进仓库** ——
于是这些判据对**将来的改动**没有任何约束力。实测：

> 把兜底网从主循环里摘掉，当时四条常驻测试**全绿**。

这正是本仓老教训「**守卫只钉『名字在不在』挡不住行为被改掉**」的另一副面孔。

## 第十八轮（codex）：shell 的引号拼接 —— 同一条根的**第四次**命中

### 缺陷

```sh
psql -c "INSERT INTO training_sets (stock_code, /""* schema_version, *""/ stock_name, …) VALUES (…);"
```

shell 会把 `/""*` 拼成 `/*`、`*""/` 拼成 `*/` —— 运行时 `schema_version` **在注释里**，
PostgreSQL 用 `DEFAULT 1`。而**源码里看不出任何注释**，守卫把它当成在场的列 ⇒ **假绿**。

### 这是「源码文本 ≠ 运行时字符串」的第四次命中

| 轮次 | 宿主 | 形态 |
|---|---|---|
| 11 | `.py` | 相邻字面量拼接，`--` 注掉了下一段里的 `schema_version` |
| 16 | `.py` | `--` 后是**转义**换行，源码里没有物理换行 |
| 17 | `.py` | **注释定界符本身**被劈开 |
| 18 | `.sh` | **shell 的引号拼接**拼出了一对注释定界符 |

第 17 轮我给 `.py` 上了精确解（语法树）。**但只修了 `.py` 那一层** ——
`.sh` / `.yml` / `.md` 同样会拼接，而我当时没有回头问「**别的宿主呢**」。
（本仓老教训：**改动只落在报告的那一处，没落在整条判据家族上**。）

### 修法：不再逐种写法去猜，改成【判不了就说判不了】

`.py` 有精确解；`.sh` / `.yml` / `.md` **没有**（要真正判准得给每种宿主写词法器，
在 TS1-R1 落地前不值得）。⇒ 这些宿主的列清单里只要出现**宿主引号**或 `--`，
一律断言「**判据够不着**」让测试红。

原先只有 `--` 一条，现在提成一个具名判据 `_ambiguous(cols)`，
报文会说清是**哪一种**歧义。

⚠️ **实测：干净树上 11 条非 `.py` 列清单一个引号都没有** —— 这条规则零代价。
⛔ 这一步我是先量了再做的：一道会在干净树上变红的守卫，等于给实施者发放宽许可证。

### 验证

- codex 报文里的**原样样本**现在报「判据够不着（列清单含 宿主引号…）」，不再报绿；
- 三条新语料（双引号拼块注释 / 单引号拼块注释 / 拼行注释）进常驻测试；
- **变异**：把 `_ambiguous` 里认引号那一支关掉 ⇒ `known_evasions_never_produce_a_false_green` **变红**
  ⇒ 这条规则是承重的，不是装饰。
- 12 组变异复跑，**全部变红**，红的仍是对症的那一条。

## 第十九轮（codex）：反斜杠续行 —— 以及我为什么把判据**反过来**写

### 缺陷

```sh
psql -c "INSERT INTO training_sets (stock_code, /\
* schema_version, *\
/ stock_name, …) VALUES (…);"
```

bash 会删掉「反斜杠 + 换行」，于是 `/` 与 `*` 在运行时拼成 `/*`、`*/` ——
`schema_version` 落在注释里，PostgreSQL 用 `DEFAULT 1`。源码里同样看不出注释。

### ⭐⭐⭐ 这是我第五次往「歧义字符集」里补字符

`_ambiguous` 的演进史：宿主引号 → `--` → ……→ 反斜杠续行。
**每一轮我都在枚举攻击面**，而「**数不完**」这四个字就写在本文件自己的注释里 ——
我对发现层认了这个道理（第 13 轮换掉全局抹除）、对 `.py` 判定层认了（第 17 轮换语法树），
**唯独对「非 `.py` 宿主的列清单」这一处，连栽两轮还在补字符**。

⇒ **把判据反过来写**：不枚举什么是歧义的，枚举**合法列清单里只能有什么**。

```
合法列清单 ⊆ { 标识符字符, $, 逗号, 括号, 空白 }
```

这是**封闭集合**。任何别的字符（引号 / 反斜杠 / `-` / `/` / `*` / `;` / `%` / …）
在无法逐字还原的宿主里一律判「**判据够不着**」。

### ⛔ 先量后做

实测：干净树上非 `.py`/`.sql` 宿主的 **11 条列清单，没有一条含集合外字符** ⇒ 零代价。
（一道会在干净树上变红的守卫等于给实施者发放宽许可证。）

### 反转之后顺手关掉的三种，本来会是第 20、21 轮

我自己又试了三种同族写法，**全部**落进「判不了」：

| 形态 | 说明 |
|---|---|
| `$'…'` 转义串 | bash 的 ANSI-C quoting，`\x2f` 就是 `/` |
| 列清单里出现分号 | `(stock_code; file_path)` |
| 列清单里出现百分号 | `(stock_code, %s)` 这类宿主占位符 |

⇒ 枚举**合法面**的价值就在这里：它对**没见过**的攻击同样成立。

### 变异验证

| 变异 | 变红的测试 |
|---|---|
| N1 正字符集放宽成任意字符 | 主判据 · 攻击语料 |
| N2 `_ambiguous` 恒返回 None | 攻击语料 |
| N3 歧义规则不作用于 `.sh` | 攻击语料 |
| N4 `prose` 出口不钉数量 | **零红 —— 预期如此** |

⚠️ N4 零红是**预期**的，不是缺口：`assert prose == 1` 与 `assert whitelisted == 2`
是给**将来新增项**准备的绊线，当前树上恰好各有 1 / 2 条，拿掉断言当然没人红。
⛔ 所以**不能**说它们「已被变异验证」—— 它们的判别力靠的是算术（多一条就 ≠），
   已单独核验计数器本身有判别力（散文文本 ⇒ `prose=1`，真语句 ⇒ `checked=1`）。

⚠️ 另：我这版变异收集器**只认 `FAILED` 不认 `ERROR`** —— N4 的变异写法其实会让
文件语法出错，被收集成 `ERROR` 而不是 `FAILED`，于是显示成「零红」。
结论没受影响（N4 本来就该零红），但这正是本仓记过的老坑，记在这里。
