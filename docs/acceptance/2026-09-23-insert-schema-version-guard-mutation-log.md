## 判据分三层，每层都是被实测打出来的

### ① 发现层：正则，不是固定字面量

`text.find("INSERT INTO training_sets")` **区分大小写**，且只认「`INTO` 与表名之间恰好一个空格、无 schema 限定」一种拼法。实测：小写 / 换行 / `public.` 三种**合法且缺字段**的写法**全部溜过**，而既有 12 处仍满足防空转计数 ⇒ **新写入方可静默绕过**。

### ② 判定层：按【列名集合】，不是子串

一句 `/* schema_version uses the default */` 注释就能把子串判断喂饱，而**真列并不在场**。
⇒ 先剥 SQL 注释（`/* */` 与 `--`），再按逗号切 token、剥引号后按**整个标识符**比对。
⭐ 所以一个叫 `my_schema_version` 的列**不会**被误判为通过（变异已验）。

### ③ 兜底层：一张故意放宽的粗网

精确正则再宽也总有够不着的拼法（表名被劈成 `"INSERT INTO training_"` + `"sets …"`）。
⇒ 凡「像是往 `training_sets` 写」却**没被精确正则认领**的，一律报「**判据够不着**」**让测试红**。
⛔ **不许把「断定不是目标」和「判据够不着」混进同一个分支** —— 两者会互相伪装成对方。宁可偶尔误报（红了有人看），也不要漏报（绿了没人知道）。

## 第五次攻破后：发现层换做法（不再往字符类里补字符）

Codex 再次判 **needs-attention**：`INSERT INTO public./* target table */training_sets`
—— **schema 限定符与表名之间夹注释**，同时绕过精确正则与粗网。**我复现了。**

### ⚠️ 到这里必须承认：我一直在打地鼠

发现层被攻破的**五次**，每一次我的反应都是「往间隔字符类里再补一个字符」：

| 次 | 攻破形态 | 我当时的补法 |
|---|---|---|
| 1 | 大小写 / 换行 / `public.` 限定 | 固定字面量 → 正则 |
| 2 | 关键字之间夹注释 | 间隔类补 `/* */`、`--` |
| 3 | `+` 拼接 | 间隔类补 `+`、`\` |
| 4 | 表名被劈开 | 加粗网兜底 |
| 5 | **限定符与表名之间夹注释** | ← 如果继续，就是再补一个字符 |

**字符类永远数不全。** ⇒ 换**结构性**做法。

### 新做法：先抹平、再用简单正则

先把**干扰物**换成**等长空白**（位置 1:1 保持、换行保留 ⇒ 行号不会错），再扫抹平后的文本。干扰物只有两类：
1. SQL 块注释 `/* … */` —— 可以出现在语句的任何缝隙里；
2. Python 字符串拼接的痕迹 `"` `'` `+` `\` —— 它们**永远不属于标识符**。

抹平之后，发现层只剩一条**简单**正则：

```
insert(?:\s|--[^\n]*\n)+into(?:\s|--[^\n]*\n)+(?:public\s*\.\s*)?training_sets
```

⚠️ **等长是硬要求**：抹平后的下标要能直接映射回原文，否则报出来的行号是错的。
⚠️ `--` 行注释**不做全局抹平**（它在 shell / YAML 里另有含义，全局抹会吃掉同一行后面的真 SQL ⇒ 制造**漏报**）；只在关键字之间的间隔里局部容忍。

⭐ **换完之后实现反而更简单了** —— 手工调出来的一长串字符类没了。

## 第六次攻破：表示空白的**转义序列**

Codex 再判 **needs-attention**：`"INSERT INTO\\ntraining_sets (…)"` —— Python 字面量里的
`\\n` 执行时是**合法 SQL 换行**，但**源码文本里是反斜杠 + 字母 `n` 两个字符**。
抹平只抹掉了反斜杠，留下一个 `n` ⇒ 发现层当场瞎掉。**我复现了。**

**修法**：按**整个转义序列**抹成等长空白，而不是只抹反斜杠。
⛔ 次序有讲究：空白转义必须在单字符拼接痕迹**之前**处理 —— 否则反斜杠先被抹成空格，留下的 `n` 就再也认不出来了。

⭐ **这一类是可穷举的**（与前五次不同）：SQL 里的空白只有 空格/制表/换行/回车，对应的转义写法就那么几种。

| 变体 | 结果 |
|---|---|
| `\\n`（codex 报的）· `\\t` · `\\r` · `\\x20` · `\\u0020` · `\\040` 八进制 | 6 / 6 ✅ |
| 多个转义连用（`INSERT\\nINTO\\ttraining_sets`） | ✅ |
| 转义 + `public.` 限定 | ✅ |

**8 / 8 为红，0 漏掉。** 干净树 `1 passed`；整套后端 `1506 passed`。

## 第七次攻破：schema 限定符**点号周围**的行注释

Codex 判 **needs-attention**：`INSERT INTO public. -- target table\ntraining_sets (…)` 是合法 SQL，
而点号两侧我只写了 `\s*`。**行注释是故意不做全局抹平的**（它在 shell / YAML 里另有含义），
所以必须在这里**局部容忍** —— 我上一轮改点号那处时只想到块注释（已被抹平），漏了行注释。

**修法**：点号两侧改用与关键字之间**同一种**间隔 `(?:\s|--[^\n]*\n)*`。
⚠️ 用 `*` 而非 `+`：没有间隔（`public.training_sets`）才是最常见写法。
